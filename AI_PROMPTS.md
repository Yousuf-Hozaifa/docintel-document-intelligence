# AI prompts and disclosure of AI-assisted development

## 1. Disclosure statement

This project was built with heavy AI assistance. **All source code, tests, evaluation tooling, synthetic-data generators, diagrams and documentation in this repository were written by an AI assistant (Claude, from Anthropic, used through the claude.ai chat interface with a code-execution sandbox)** in response to the prompts reproduced in section 2. The assistant also ran the tests, benchmarks and evaluation in its Linux sandbox and wrote up the results. Exact model name(s) and dates: _candidate to add from the chat history._

- **The application itself does not use any AI at run time.** Extraction is rule-based; there are no LLM or paid-API calls. An optional semantic-search backend uses downloaded GloVe word vectors (a numeric lookup table); an adapter for `sentence-transformers` exists in `backend/app/semantic.py` but was **never executed** (model hosts were unreachable from the sandbox).
- **All evaluation data is synthetic**, generated by deterministic scripts (`eval/make_dataset.py`, `backend/synth/`), not by an LLM and not copied from real documents.
- **What was and was not verified by execution:** tests, benchmarks, the evaluation and the UI flows were run in the assistant's Linux sandbox (1 CPU core, 4 GB RAM) using headless Chromium. **Nothing was run on the Windows / 8 GB target machine by the assistant.** Where results depend on that machine they are marked unmeasured (see `docs/benchmarks/WINDOWS_RUNBOOK.md`).
- The assistant reported its own mistakes as they were found (section 3). Numbers in the documentation come from recorded runs (`docs/benchmarks/`, `docs/evaluation/`, `docs/test-results/`), not from estimates.

## 3. Mistakes made by the AI assistant during development (found by tests/measurement and corrected)
1. **Inflated memory measurement:** the first semantic-search load benchmark imported PyMuPDF inside the timed region (115 MB reported; corrected: 22 MB).
2. **Wrong performance claim:** the assistant first reported a 45% slowdown after a refactor by comparing two different timing harnesses; re-measured with the same harness, no regression was found, and the docs were corrected.
3. **Evaluation setup bugs:** spreadsheets in the generated data lacked a currency that the label asserted; expected validation rules were keyed differently from predicted ones; one metric counted correctly flagged duplicates as false alarms. Found on the dev split and fixed before the held-out run.
4. **Weak or vacuous tests:** an assertion that could never fail (`or True`), a status-in-(200, 404) assertion, and a path-traversal test that did not actually reach the secret file were found in review and replaced; the final tests are mutation-checked (they fail when the production code is deliberately broken).
5. **Evaluation circularity risk:** the extractor and the test data share an author. The report states this, uses a dev/test/fresh-test protocol, and labels results derived after inspecting test errors as post-hoc.
6. **Real product gaps found late:** no way to delete a document, no pagination for large documents, and no way to view the original file during review were added after the first complete version.
